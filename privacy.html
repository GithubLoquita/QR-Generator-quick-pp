Privacy Policy

QR Studio ("we", "us", or "our"), developed by Sandip Hembram, System Software Engineer, prioritizes user privacy through client-side architecture. This policy details how your technical data, files, and browser interactions are handled.

1 Data Controller & Developer Identity

The platform is an initial project developed and maintained by Sandip Hembram, System Software Engineer (operating the website https://qrenerator.vercel.app/). For data protection, compliance inquiries, or security matters, our designated contact is hembramsandip990@gmail.com.

2 Local In-Browser Processing (Zero Server Transmission)

All primary core features of QR Studio operate entirely within the client's local browser environment:

  • QR Code Generation: Generated locally via mathematical algorithms rendering into HTML Canvas and SVG elements (qr-code-styling).
  • Barcode Generation: Rendered into inline SVG elements via client-side libraries (JsBarcode).
  • Image to PDF Conversion: Local files are parsed into client memory via the native FileReader API and compiled directly into PDF binaries using jsPDF.
  • Merge PDF Tool: Files are read as in-memory ArrayBuffer structures and assembled into combined PDF documents using pdf-lib.

Your files, images, documents, text strings, Wi-Fi credentials, contact details, and generated codes are never uploaded, mirrored, or transferred across the network to our servers or any third-party conversion API.

3 Zero Account Creation & Zero Payment Information

QR Studio is 100% free for public use without requiring user accounts, passwords, identity registration, telephone verification, or payment cards. We do not maintain user profile databases or monetary transaction records.

4 Elimination of Third-Party Telemetry & External Counters

In accordance with our strict data-minimization architecture, all external tracking endpoints (including former CountAPI polling scripts) have been removed from this website. The application initiates zero unsolicited background tracking calls, zero analytical beacons, and zero telemetry pings.

5 Edge Hosting Provider Infrastructure Logs (Vercel Inc.)

QR Studio is statically hosted on edge infrastructure provided by Vercel Inc. When a browser requests static website assets (such as HTML, CSS, JavaScript bundles, or icons), Vercel's edge network automatically processes standard HTTP request headers. These technical logs may include your IP address, browser type, referral header, and timestamp for network routing, DDoS defense, and infrastructure security, handled subject to Vercel's Privacy Policy.

6 External Typography & Font Delivery (Google Fonts)

To ensure readable, high-contrast typography, the website requests standard web fonts ("Plus Jakarta Sans" and "JetBrains Mono") from Google Fonts CDN (fonts.googleapis.com and fonts.gstatic.com). When downloading fonts, your browser transmits standard connection headers to Google servers under Google's Privacy Policy.

7 Local Browser Storage (localStorage)

We use strictly local storage on your client device solely to persist essential operational choices:

Key Classification Function
qr_studio_terms_consent Essential Stores acknowledgment of terms version to prevent repetitive modal interruptions.
qr_studio_file_upload_consent Essential Stores user confirmation of lawful file rights prior to file processing.

You may clear these keys at any time through our "Privacy Choices" modal or via your browser's site settings.

8 Zero Tracking Cookies

QR Studio does not set, read, or distribute any HTTP tracking cookies, marketing beacons, or cross-site profiling trackers.

9 Memory Lifecycle & Instant Cleanup

Uploaded images and documents reside strictly in volatile browser RAM using temporary Object URLs. When you remove a file item, click "Clear All", or navigate away/close the browser tab, the application triggers URL.revokeObjectURL() to promptly release system memory.

10 File Safety Boundaries & Resource Limits

To safeguard user devices against decompression bombs, memory exhaustion, or format exploits, QR Studio enforces explicit client-side resource quotas:

  • Image to PDF: Max 50 files per batch; max 25 MB per individual file; max 100 MB aggregate batch; max 8,192 px dimension / 32 Megapixels. Magic-byte inspection verifies genuine JPEG, PNG, or WebP binary formats.
  • Merge PDF: Max 30 files per batch; max 50 MB per file; max 150 MB total. Magic-byte verification checks for valid %PDF- headers.
  • QR Embedded Logo: Max 5 MB; max 2,048 px dimension with verified image signatures.

11 DOM Security & XSS Remediation

The application utilizes strict DOM APIs (document.createElement, textContent, and programmatic event listeners) for dynamic rendering of file lists, eliminating DOM-based cross-site scripting (XSS) risks from untrusted file names.

12 User Responsibility & File Ownership Rights

Users are solely responsible for ensuring that all documents, photographs, and logos processed via QR Studio do not infringe third-party copyrights, trade secrets, privacy rights, or statutory laws. Users are advised not to process sensitive unredacted government credentials on unmanaged or shared public workstations.

13 Children's Privacy Protection

QR Studio does not knowingly collect, record, or retain any personal information from children under 18 years of age (or under 13 in jurisdictions with specific COPPA/digital safety legislation). Since all tools execute client-side, we store no repository of minor user records.
